# Changelog

## Unreleased

### Features

- **Click a context's gutter icon to jump to its definition**: The context icon in a branch's gutter is now clickable — it selects, scrolls to, and flashes the context's declaration branch wherever it lives in the tree, expanding any collapsed ancestors on the way. An inherited context jumps to the original declaration, not the branch you clicked from. Built-in contexts (Basic review, Basic execution) have no declaration branch, so their icons stay non-clickable.
- **Review AI revisions inline on the branch**: When you send a branch for review (Collaborate or Collaborate & Execute, or a manual terminal/MCP send), the AI's proposed revision appears in place on that branch — its subtree shown with green/blue/red change highlighting and an **Accept / Cancel** bar in a row directly above it. Accept applies the revision (undoable with `Ctrl+Z`); Cancel discards it and leaves your branch untouched. You can edit the proposed branches before accepting, with no context switch and no focus jump when the proposal updates. Decomposition — splitting one branch into several — shows the proposed branches inline in place of the original, reviewed the same way. Reviews run concurrently: keep several open at once and accept or cancel each independently (a second proposal for a branch already under review replaces it in place), as long as they don't overlap — you can't review a branch while it, an ancestor, or a descendant is already under review. Terminal/MCP reviews are concurrent; browser-panel reviews stay one at a time.
- **Claude sessions resume automatically on relaunch**: When you reopen Arborescent, every open file's terminals come back with their Claude session already resumed — not just the file you were viewing, and with no file switch needed. Each terminal reopens in its working directory and runs `claude --resume` once its shell prompt is ready; the resumes run in the background and are throttled, so the window is interactive immediately even with many sessions across several files. A terminal whose session is gone from Claude's store, whose folder no longer exists, or that never had a session reopens quietly as a plain shell — no error and no per-terminal toast storm. Previously only the active file's terminals respawned, as dead shells you had to relaunch and resume by hand.
- **Autonomous steps can ask for more reasoning effort**: When an autonomous execute step judges the task has outgrown the reasoning effort it was started with, it pauses on the existing review hook instead of pushing through at low effort, and its terminal summary asks you to raise Claude Code's reasoning effort (or switch to a more capable model) and **Resend step**. Manual, collaborate-only, and browser sends are unaffected.
- **Manual workflow steps support Start and Resume**: Right-click a manual step → **Start Workflow** sends the step's content to a terminal and pauses the workflow at the step — the same paused state checkpoint uses. From the paused state, **Resume Workflow** re-sends on the same bound terminal and **Next step** advances. Previously manual steps had no Start affordance and the workflow halted with no binding — ad-hoc **Send** was the only way to relay the prompt, and it could land in any session. Ad-hoc **Send** still works for one-off relays that don't enter the paused state.
- **Per-step workflow history keeps prior runs restorable, out of Cmd+Z**: Each workflow step now keeps the last 10 changes it made as a browsable history attached to the step itself. `Ctrl+Z` reverts only your own actions — workflow output stays in step history instead, so a workflow run can never erase a manual edit you wanted to undo. Right-click a workflow step → **Step History** to browse entries (labeled by the original parent's content, with a hover-time tooltip) and click one to restore a deep copy as a child of the step. The current node and its terminal session are untouched by restoration; `Ctrl+Z` removes the restored copy cleanly. The starting step captures the workflow's input; each mutating step captures the pre-mutation state; checkpoint accepts capture the pre-accept state; decomposition captures the pre-decomposition parent and seeds each new sibling's initial state. Deleting a step keeps its history attached for undo, and existing `.arbo` files without history open normally.
- **Backticked content renders as code in branches**: single backticks render their contents as inline monospace code with a subtle background; triple-backtick fenced blocks render as multi-line code blocks with preserved whitespace and indentation. An optional language hint on the opening fence (`` ```ts ``, `` ```bash ``) is accepted and hidden, though no syntax highlighting is applied yet. Styling uses the existing theme tokens, so light and dark themes both look right. Selecting a branch to edit drops back to plain text so the raw backticks stay visible while you type, and unmatched backticks render literally — runaway markup can't eat the rest of the content. Inline URLs and search highlight pass through the same render pipeline and continue to work alongside code spans.
- **Terminal scroll lock starts off, snaps to bottom on toggle-on**: new terminals open unanchored so scrolling back through output during a stream no longer requires unpinning first. Click the anchor icon when you want to follow the bottom of the buffer; click again to release. Toggling on also reconciles the viewport immediately — previously the view stayed parked on stale rows until the next keystroke arrived.
- **Claude Code can read your tree via MCP**: Arborescent-driven Claude sessions get three read tools — `get_node` (the bound node's content, metadata, and current effective mode), `get_tree` (subtree with an optional depth cap, capped at 100), and `list_contexts` (contexts in scope with the applied one first). Claude's session ID is injected into its context on session start so it can call these tools without your involvement. Read tools work in any mode (execute, collaborate, action).
- **Claude Code can edit your tree via MCP**: Arborescent-driven Claude sessions now get seven tree-modifying tools — `add_child_node`, `append_to_node`, `mark_step_complete`, `set_node_content`, `delete_node`, `move_node`, and `set_node_metadata` — plus two workflow-stepping tools: `submit_step_output` (collaborate steps, carrying the reviewed content as one revised list) and `announce_step_done` (collaborate & execute, execute-only, and action-mode steps, signalling completion without content). Each step mode owns exactly one completion channel and one set of permitted edits, enforced server-side: Collaborate routes everything through the single submit (on autonomous steps incremental edits are refused so the rebuild can never overwrite them); Collaborate & Execute works incrementally — additions and check-offs only, with `mark_step_complete` taking an optional `node_id` to tick an individual item — and completes via announce, so nothing the AI adds mid-run is lost to a final rewrite; Execute blocks every edit; Action doesn't bind so no edits happen. A tool call outside the step's mode gets a refusal naming the permitted alternative. Successful edits apply directly to the tree on autonomous workflow steps; on manual or checkpoint steps the tools surface the proposal inline on the bound node for you to accept or reject (see "Pending proposals from Claude" below).
- **MCP tool failures carry stable error codes**: Every refused or failed MCP tool call now returns a machine-readable code (`write/unbound`, `write/mode-refusal`, `write/target-drift`, …) in a structured field alongside the human-readable reply, and logged failures emit the identical string as `code=<code>` — so an agent can branch on the failure instead of pattern-matching prose, and you can grep the log for exactly the refusal the agent saw. Codes are stable and additive; the prose may be reworded freely.
- **Pending proposals from Claude surface inline**: When Claude calls a tree-modifying tool or `submit_step_output` while bound to a manual or checkpoint step, the request appears inline on the bound node as a proposed revision with an **Accept / Cancel** bar. Accept routes the change through the normal command pipeline so `Ctrl+Z` undoes it like any other edit. Cancel discards it without touching the tree. Proposals are scoped to the file the bound node lives in, so switching tabs only shows proposals for that file. Claude cannot see pending proposals through any MCP read tool — `get_node`, `get_tree`, and `list_contexts` keep returning the applied tree state until you accept.
- **Manual sends keep the workflow's binding**: Right-click → **Send** and **Revise after discussion** on a node route the AI's response back to that node without disturbing whichever node the terminal's workflow is bound to. Previously, a manual send on a terminal running a workflow could land the response on the workflow node and open the rebind confirmation dialog mid-turn. Action-mode sends still preserve the binding as before. Manual-send responses always arrive as an inline review on the target branch — even when the target sits under an autonomous workflow step — so a one-off send can never overwrite a node's subtree without your approval.
- **Terminal close asks before discarding an in-flight prompt**: Closing a terminal whose AI prompt is still processing now opens a confirmation dialog naming the terminal — **Keep open** keeps the session, **Close anyway** tears it down and abandons the in-flight response. Closing an idle terminal (no prompt running, or just bound to a node) closes immediately with no dialog, as before. Both the `×` button on the tab and the close-tab keyboard shortcut now route through the same guard.
- **Rebind confirmation only on workflow-start, never mid-run**: Starting a workflow on a terminal whose Claude session is already bound to a different workflow node opens a dialog naming both nodes before the binding switches. **Keep current** preserves the existing binding; **Rebind** switches the session to the new node. Nothing is sent and the tab keeps its current binding until you choose. The dialog no longer appears during a running workflow — sibling hand-offs from decomposition + recurse, step advances, manual sends, and freeform iterations all route silently. While the dialog is open on a terminal, sends to that terminal are blocked with a toast so a stray send cannot race a still-pending binding.
- **Workflow controls follow Claude restarts in real time**: Restarting `claude` inside a terminal (exit and re-launch, `/clear`, or a fresh session in a tab that already had one) updates Arborescent's view of which session lives in which terminal on the next prompt. **Resume session**, **Start Workflow**, and the active-terminal stripe now refer to the live session immediately, not the dead one from before the restart.
- **Send to workflow**: Right-click any branch → **Send to workflow** lists every workflow in the current file and moves the branch (and its subtree) under the chosen workflow's first step. The view jumps to the destination and flashes the moved branch on arrival. Attached contexts on the branch and its descendants survive the move. The submenu excludes the branch itself and any workflow nested inside its subtree to prevent cycles. Undoable with `Ctrl+Z`.
- **Workflow steps drop the bespoke node icon**: A workflow step row now shows only its step number, label, and — when a context is applied — the context's gutter icon. The per-step icon picker (and the row-level node icon for steps) is gone; the gutter is the single visual signal for context attachment on every node type. Existing `.arbo` files migrate on load: persisted icons on workflow-step descendants are dropped silently, workflow roots and context declarations keep theirs.
- **Activity log for workflow and hook events**: Arborescent now keeps a persistent log of every hook request, workflow event, and drop reason at `<userData>/logs/arborescent.log`. Open it with **Help → Open Log File**. Each line is tagged with the workflow node it concerns when one was resolvable, and dropped hooks carry an explicit reason (`no terminal mapped`, `no running node`, `invalid auth token`, `invalid payload body`) so you can tell apart a hook that never arrived from one that arrived and was discarded. The file rotates at 5 MB and keeps the three previous logs alongside it. Attach to bug reports when a workflow stalls.
- **Resend step and Next step replace Continue Workflow**: A paused workflow step (awaiting checkpoint validation) now offers two distinct right-click actions. **Resend step** re-sends the current step's content on the same terminal without advancing — use this when the AI paused with a question and you want to answer it in place. **Next step** advances to the next workflow step and resumes execution there. Previously, a single **Continue Workflow** action silently advanced past unanswered AI questions. **Next step** is now visible from paused checkpoints in addition to idle workflow steps.
- **Terminal tab labels track the task**: Sending or executing a branch to a terminal renames the tab to that branch's title (full title on hover), so concurrent task tabs are distinguishable at a glance. The tab follows the branch's title as it changes — your renames and AI updates through MCP alike — and keeps the title until the next branch is sent.
- **Revise after discussion shortcut**: Right-click → **Revise after discussion** sends the branch with a one-shot revision prompt ("revise this spec based on our discussion, mark completed items as done, leave the rest intact") instead of the branch's applied context. The applied context isn't changed — it's a single send, not a state change. Replaces the Apply context → Send two-step for the most common iteration loop during spec or PRD work.
- **Auto-launch Claude on Start in a fresh terminal**: Starting a workflow on a terminal that has no Claude session yet now launches `claude` automatically and sends the first prompt once the session is ready — previously the prompt landed at the shell and the step had to be stopped manually. Terminals already running Claude are unaffected. If `claude` isn't on your PATH the prompt still lands at the shell and the step needs to be stopped from the right-click menu. The **Clear AI session** step option is skipped on this path since the new session is already clean; reattaching to an existing session still runs `/clear` as before.
- **Recurse stays in the same AI session**: When a recurse-enabled workflow advances to the next decomposed sibling, the new step inherits the previous sibling's Claude session so prior turns stay in context. If the originating tab was closed, recurse opens a fresh tab in the recorded working directory and resumes the same session there. If the parent session is unrecoverable, the new step starts fresh and a toast tells you the chain was broken. Resuming a chain (manually or as part of a recurse advance) rebinds every chain member to the new tab in one step.
- **Auto-resume on Start Workflow**: Clicking **Start Workflow** on a node that already has a live AI session now focuses the existing tab instead of spawning a duplicate. If the tab was closed but the session is still on disk, Start opens a new tab and runs `claude --resume`. A fresh session is only spawned when the node has no recorded session or its session has been lost. Stopping a workflow leaves its CLI session running; the next Start picks up the same conversation rather than starting over.
- **Resumable AI sessions per workflow step**: Each workflow step captures its AI session id on the node and persists it across app restart. Right-click a workflow node → **Resume session** opens a new tab in the recorded working directory and runs `claude --resume`. The entry only appears once the session's original tab has been closed — while the tab is still open, just switch to it. Closing a terminal tab no longer ends the underlying session — you can walk away from a running step and come back to it from any tab. If the session can't be resumed (gone from Claude's session store, or recorded directory removed), a toast appears at the moment of failure; start the workflow again to spawn a fresh session.
- **Run a branch as a terminal command**: A branch whose whole content is a single backticked snippet — `` `npm install` `` for a one-liner, or a triple-backtick block for multi-line — now runs in the terminal as a raw command with the wrapping backticks stripped, instead of being sent as markdown chrome (`# [ ]` heading and all). The branch must have no children and no applied context, and the gesture only fires on single-branch selections; multi-select, children, or an applied context all revert to the regular markdown send. Empty backticked branches send nothing.
- **Active terminal highlights its bound node**: When a terminal tab is active, the tree marks the node it's bound to with a thin blue stripe on the left edge. The binding is set when the terminal is opened from a node (Send, Start Workflow, Resend step, Resume Session) and lasts the lifetime of the session — the stripe stays visible across idle periods after a workflow step finishes. A workflow step actively running on the tab takes precedence over the original binding. Focusing the bound node from the tree gives its terminal tab a subtle blue tint, even when a different tab is active — so the pairing is visible from either side. Switching tabs moves the stripe; selection is unaffected.
- **Inline review highlights changes**: When an AI revision is under review, modified branches show with a blue background, added branches with green, and removed branches with a red background and strikethrough at the position they used to sit. Branches the AI returned untouched keep their original identity, so selection, expansion state, and internal hyperlinks to those branches survive across review rounds (and `.arbo` diffs in version control stay much smaller).
- **Four context states (Collaborate / Execute / Collaborate & Execute / Action)**: Contexts now have two independent toggles for whether the AI is asked to propose tree updates and whether it's asked to make code changes. The four resulting states surface as named items in the right-click context-mode submenu. Action — neither toggle on — sends the context body as a standalone instruction (no scaffolding, no branch content), useful when the context itself is the prompt. Existing `.arbo` files migrate on load: the previous Execute mode becomes Collaborate & Execute, preserving the long-standing "implement and check off" behaviour. Built-in **Basic execution** is now Collaborate & Execute; **Basic review** stays Collaborate.
- **Inline URLs in branches**: http(s), vscode://, and mailto: links inside any branch are now clickable while the branch isn't selected — they open in your default app. Pasting a URL no longer turns the branch into a link-only node, so URLs survive sends to AI and markdown export. Internal node-to-node hyperlinks (Copy as Hyperlink) are unchanged.
- **Workflow execution**: Declare blueprint branches as workflows with numbered steps, assign step types (Manual, Checkpoint, Autonomous) to control automation level, and run items through workflows with automatic advancement via AI tool hook integration. Supports nested workflows and parallel execution across terminal tabs
- **Keep computer awake during autonomous workflows**: While at least one autonomous workflow is running, the system is prevented from suspending so background AI work isn't interrupted. The block is released as soon as the last workflow finishes, errors, or is stopped. The display can still sleep — only system suspension is blocked.
- **Workflow disruption handling**: Running workflows stop gracefully when their terminal is closed, the item is moved or deleted, or the app restarts. Checkpoint items awaiting validation are preserved across restarts. Toast notifications explain what happened
- **Step configuration dialog**: Click a workflow step number to open a configuration dialog for that step, with step type selection, decomposition, recurse, and archive settings
- **Decomposition mode**: Enable decomposition on a workflow step to break a node into multiple sibling nodes from a single AI response. Useful for turning problem statements into user stories, specs into test cases, etc.
- **Archive with provenance**: Configure a workflow step to archive the original node before replacing it. The original is moved to a designated location with bidirectional hyperlinks connecting it to each replacement. Navigate the transformation chain by clicking the links. Fully undoable.
- **Recurse**: Pairs with decomposition. When an earlier step decomposes a node into siblings, enabling recurse on a later step automatically picks up each waiting sibling and runs it through the remaining steps one at a time. Recurse without decomposition is a no-op and surfaces a toast warning so you can fix the configuration. Includes a 50-iteration safety limit.
- **Clear AI session per step**: Enable Clear AI session on a workflow step so it runs against a fresh AI session — no context from prior turns. Useful for long chains or when you want a predictable starting state. Carries through blueprints. Requires a small update to the SessionStart hook (see docs/workflows.md Hook Setup).
- **Auto-accept for autonomous collaborate steps**: When an autonomous workflow step uses a collaborate-mode context, the AI's feedback is accepted automatically — the node content is replaced and the workflow advances without surfacing a review. Supports concurrent autonomous collaborations across multiple terminals. If feedback can't be parsed, the workflow pauses with an error instead of advancing with stale content.
- **Workflow context menu**: Workflow-related actions (Declare/Remove, Configure Step, Next/Previous step) are now in a dedicated "Workflow" submenu in the right-click menu. Start, Stop, Resend step, and Next step remain at the top level for quick access.
- **Simplified workflow state model**: Workflow execution uses a two-state model (running / awaiting-validation) instead of three states. Context menu shows Start, Stop, Resend step, and Next step actions
- **Unified context modes**: Collaborate and Execute modes are now defined on context declarations instead of at send time, simplifying the send menu and making mode a property of the context itself
- **Simplified Send action**: Send is now a single menu item that routes to the active panel (terminal or browser). Hover to see the current mode and applied context name. Replaces the previous submenu with In terminal/In browser options
- **Apply context submenu grouping**: The Apply context submenu groups contexts into up to four sections by their state — Actions, Execute, Collaborate, and Execute & Collaborate. Sections without contexts are omitted. Built-in defaults sit inside the matching section: Basic execution under Execute, Basic review under Collaborate. Built-in defaults are hidden when a context is inherited. Submenu scrolls when content exceeds viewport height
- **Context indicator refactor**: Context declaration and applied context indicators consolidated with clearer visual hierarchy and tooltips
- **Desktop notifications and sounds**: OS desktop notifications and audio alerts for workflow completion, errors, NeedsReview, and timeouts. Configurable via File → Preferences toggles for desktop notifications and notification sounds (both on by default). Notifications are suppressed when the app is focused.
- **Execute mode feedback loop**: Terminal execute mode now uses the same round-trip pipeline as collaborate — the AI's submission appears as an inline review, or auto-applies on autonomous workflow steps. Accept is undoable. The AI updates item statuses without rewriting your content.
- **Per-file panels**: Each open file now has its own panel state. Opening a terminal in one file and switching to another shows no panel — each file remembers which panel was open independently. Panel position and size remain global. Zoom tabs share their parent file's panel.
- **Per-file session persistence**: Panel visibility, browser tabs, and terminals are now saved per file and restored on restart. Terminals reopen in their original working directory (history is lost). Browser tabs remain scoped to the correct file.

### Bug fixes

- **Decomposed/recurse siblings hand off cleanly after one finishes** — starting the next sibling could raise a false "Terminal tab is already assigned to a running workflow node" for a node that had already finished, and starting it in a fresh session instead resumed the previous sibling's closed session while prompting to rebind. The terminal-busy check now ignores a finished node's leftover assignment, and a hand-off that can't start leaves no stale session binding behind — so the next sibling sends on the freed terminal (or starts fresh) without the spurious toast or rebind prompt.
- **Undoing a multi-select delete restores branches in their original order** — when every child of a branch was deleted in one multi-select delete, `Ctrl+Z` brought them back shuffled (later siblings swapped positions). Undo now reproduces the exact pre-delete order. The same fix applies to undoing a cut.
- **Editing a branch during an active collaboration no longer shows a false error** — typing in a branch the AI was working on fired a "Cannot edit node in collaboration" toast on every keystroke while the text appeared to change anyway, and the typed text was silently dropped when the response arrived. Edits now apply normally; if accepting the AI's response overwrites them, `Ctrl+Z` brings them back.
- **Undecomposed items no longer stall at recurse steps** — an item that was never decomposed used to halt at an automated recurse-marked step with a misleading "handing off to next decomposed sibling" toast and never resume. It now passes through the recurse step like any other automated step. Decomposed siblings still pause there while their batch is processed — including the last one, which parks alongside its finished siblings.
- **Workflow submissions no longer silently corrupt the bound node or write to the wrong node** — an internal routing-state divergence could cause Claude's response to overwrite a workflow node with raw markdown (children left stale), land on a different node than the prompt was for, or surface an unexpected review for an autonomous step. The submit path now validates target identity end-to-end; any drift (such as an in-flight rebind you confirmed manually, or a decomposition+recurse race) surfaces as an MCP error instead of a silent wrong-node write.
- **Highlighted text inside a branch can be copied or cut on its own** — `Ctrl+C` and `Ctrl+X` (and the matching Edit menu and right-click Copy) used to always operate on the whole branch even when a substring of the rendered text was highlighted. They now respect the live text selection: cut also removes the substring from the branch content (undoable with `Ctrl+Z`). With nothing highlighted, or with a selection spanning multiple branches, both shortcuts keep their previous whole-branch and multi-select behaviour. Cut on a branch rendered with inline code or fenced blocks degrades to copy-only to avoid corrupting the source markdown — click into the branch to switch back to raw text if you need to cut there. Copy/cut from focused inputs (file rename, search, browser URL) no longer falls through to copying the active branch.
- **Ctrl+R no longer reloads the application** — the default keyboard binding for Reload Application has been removed because it was being triggered accidentally. The action stays on File → Reload Application; rebind a shortcut to it from File → Preferences → Keyboard Shortcuts if you want one. Saved preferences that still hold the old Ctrl+R default are cleared on next launch.
- **Keyboard shortcuts now work reliably on first launch** — previously, shortcuts could fail intermittently on startup, requiring a reload to fix
- **Tree-editing shortcuts no longer fire in terminal/browser panels** — cut, copy, paste, delete, select all, Escape, and view mode toggles are now properly gated when focus is in the terminal or browser
- **Pasting a hyperlink into a blueprint no longer marks the link as a blueprint itself** — a hyperlink is a reference to another node, so its blueprint status follows the link target, not where it's dropped
- **Copy as Hyperlink is now invalidated by any subsequent cut or copy** — previously a stale hyperlink could be pasted even after you copied other content over the clipboard, especially right after switching apps; pasting now reliably uses the most recent clipboard content
- **Right-click "Set context" submenu now reflects context renames immediately** — editing a context declaration's label updated the node but the submenu kept the old text until the next app restart. Undo/redo of the rename also stays in sync.
- **Switching back to a terminal tab now shows the latest output** — anchored terminals could appear stuck mid-buffer after a tab switch until you typed a key; they now snap to the bottom on reveal.
- **Copying a single leaf branch writes plain content to the clipboard** — previously copy and cut always wrote markdown chrome (`# [ ]` heading and status symbol) to the system clipboard, so pasting a single branch into Slack, email, a browser AI, or another branch's body required manually stripping the prefix. A leaf branch (no children) now copies its content as-is. Branches with children and multi-select selections still produce the markdown tree, so internal paste-back round-trips structure unchanged.

## 0.1.0 - Initial Release

First public release of Arborescent.

### Features

- Tree-based task decomposition with keyboard-first navigation
- Reusable contexts for AI instructions
- Execute and Collaborate workflows for terminal and browser AI tools
- Blueprint system for shareable workflow templates
- Integrated terminal and browser panels
- Summary mode for filtering by completion date
- Zoom mode for focusing on subtrees
- Drag and drop, multi-select, undo/redo
- YAML-based `.arbo` file format
